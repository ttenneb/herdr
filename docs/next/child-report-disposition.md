# Delegated-child missing-report disposition (#121, source contract)

**Revision note:** This records the #121 checkpoint. The subsequent #129 source work adds a compulsory fsynced `report_prepared`/prepared-attempt barrier for typed bound-parent sends and a **nonqualifying** observed-only coverage endpoint. See [the #129 entrypoint and qualification contract](child-report-prepared.md). Neither checkpoint supplies the trusted canonical Todo producer or all-path coverage needed to assert `missing_after_done_no_admitted_receipt` in production.

This is a server-owned **read-only observation**, never a Todo transition, Pi Gate admission, report submission, or parent acceptance. `agent_status=done` means only unseen idle. An empty `mailbox.history_snapshot` is settled-only history and proves nothing about an outstanding report.

## Required producer and route

The Herdr source currently has no child-local Todo completion signal and no durable server record of a report attempt before `report_submit_parent`. The Pi Todo owner must supply a provider-free producer that reports **only after** the child's canonical local Todo root is durably committed completed. It must carry a stable local root identifier and strictly monotonic local Todo revision (and ideally a digest of the committed local state), not a free-form model declaration, tool text, terminal screen state, or cached Pi session header. That producer must bridge through the foreground managed Pi's authenticated, current accepted mailbox stream; a request cannot choose its own parent, terminal, process generation, Pi session path, or route epoch. Pi must separately announce a stable attempt ID and delivery digest before any permitted report-send path can transmit, and attest a durable no-untracked-attempt coverage barrier for the completed local revision. A local attempt with no admission remains **uncertain**, not missing; a transport response alone is not a durable Herdr receipt.

Herdr resolves the authenticated child stream to the exact active child and parent delegation IDs, pane IDs, terminal IDs, process generations, full `source=herdr:pi` `agentSession` references, route revisions, and acknowledged route epoch. Revalidate that scope before each durable event and before serving a current status. Refuse stale streams, replacement processes, changed sessions, reparented/tombstoned edges, failed writer ownership, a graph restored without fresh `route_ready`, or a reused epoch. A new edge/epoch must not inherit a former completion or attempt. An old record remains readable as stale history, never as authority for current missing status.

## Durable join and read contract

Use additive records in the existing **dev-source** server mailbox append-only journal for child completion, attempt intent, and coverage barrier, under its one exclusive append lock and fsynced file/directory. The same durable stream already holds the exact `kind=report` head and **admitted** receipt, allowing a monotonic cursor over accepted record order after restart; do not race a second ledger against mailbox admission. Append must be idempotent for an exact revision/attempt and reject conflicting duplicates or decreasing revisions; loss of file ownership or an ambiguous append fails closed. Join only when delivery digest, bound grant, sender/recipient, and current route's full identity/epoch correspond to the attempted report; never infer admission from a claim or settled-only/absent history view. Any crash gap between an attempted send and its admitted receipt remains `in_flight_or_uncertain`, not `missing`.

The parent-facing disposition is one of `not_done`, `in_flight_or_uncertain`, `missing_after_done_no_admitted_receipt`, `admitted_exact_report`, or `stale_or_replaced`, with the exact matching route generation/epoch and a monotonic durable cursor. **Missing** requires a trusted durable Todo-done and coverage barrier for that exact current route and local revision, no unresolved attempt, and no admitted exact receipt after recovery. An absent attestation or missing coverage cannot be promoted to missing. Parent reads must be read-only and selector-scoped to the exact current parent route. A replayable cursor plus lightweight `disposition_changed` notification lets the parent observe transitions without a manual prompt; a lost notification is repaired by reading since its cursor after restart. Never synthesize a Todo completion or resubmit a report.

## Minimum viable verification plan (frozen before implementation)

1. **Pure decision tests**, consumed by the TPM source review: idle/done screen and empty settled history cannot produce missing; attested done without coverage is uncertain; completed+barrier+no attempt/receipt is missing; pending attempt without receipt remains uncertain; exact durable admitted receipt wins; duplicate same attempt/attestation is idempotent and conflicting duplicate fails; stale route/epoch/session/generation always stale, never missing.
2. **Authenticated socket/API tests**, consumed by the TPM and Pi owner interface review: accepted child stream selects the full route and cannot supply selectors; a forged/unmanaged/stale stream or old binding cannot attest; read-only parent status is scoped to the current parent, and cursor events do not submit or complete work.
3. **Durability/race tests**, consumed by the release gate: fsync failure and replaced writer lease never issue a completion/attempt acknowledgment; crash after attempt but before mailbox receipt is uncertain; admission readback after crash is exact; replay duplicate after restart is idempotent; new process/session/epoch invalidates old completion/attempt; cursor never decreases or falsely signals missing on recovery.

## Current server-side source slice and remaining gate

At this source revision, `src/child_report.rs` defines the full exact-route identity, conservative join, validation and statuses. Additive `child_report` records use the dev-source mailbox journal's exclusive fsynced append and recoverable record cursor. An authenticated **actual** child `report_submit_parent` records its attempt before the mailbox admission head/receipt; a crash between them is uncertain. The parent has a provider-free, read-only accepted-stream call `delegation.child_report_disposition` with `{ "protocol": "mailbox.v1", "childDelegationId": "...", "afterCursor": 0 }`; Herdr checks the current parent Pi and exact ready route, returns `{disposition:{kind,cursor,routeEpoch},changed}`, rejects a future cursor, and cannot submit or complete anything. Parent Pi may read this monotonic cursor without a model turn, but no push notification is wired yet. A replaced route returns `grant_revoked`, not the old result. Unit/socket tests exercise this source slice, not a live Pi/Herdr session.

**Unresolved required Pi-owner interface:** the canonical Todo extension must durably commit its own local root state before producing `{localRoot,localRevision,stateDigest,state}` on a current accepted child stream, with explicit `not_done` versus `done`. It must durably preannounce `{attemptId,deliveryDigest}` before **every** allowed report transport (including a send that never reaches Herdr) and certify a coverage barrier for the exact completed revision with no untracked sends. These frames may carry only Todo-local selectors; Herdr copies all Pi session, terminal, generation, parent and epoch fields from its authenticated current route. The Pi owner must specify local replay/idempotency and fsync semantics; an arbitrary child instruction or text cannot claim this authority. No mutation endpoint for these producer frames is exposed pending that trust contract. Therefore no live runtime can reach `missing_after_done_no_admitted_receipt` from current APIs: the source-only projection tests that hypothetical state, while production can expose unknown, uncertain, or an admitted exact report observed by Herdr, never trusted Todo completion or missing. A future source review must cover actual producer wiring, monotonic notification after durable append and crash replay before calling #121 complete.

No live server/Pi, provider, installed default or Pi-worktree write is authorized by this source plan. #119 non-Linux identity and #118 restart remain separate.
