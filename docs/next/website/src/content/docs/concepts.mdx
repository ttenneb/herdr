Herdr is a terminal workspace manager. It keeps real terminal processes running and adds structure around them.

## Workspace

A **Space** is one entry in the session’s ordered project list. Git directories open as a two-level Repository → Checkout Space; non-Git directories remain standalone Spaces.

A **Repository** is identified by its canonical Git common directory. Linked worktrees group automatically with their primary checkout, while separate clones and nested repositories remain separate. Its primary Checkout is the visible, clickable root of the hierarchy and uses the Repository name (including a custom rename); linked Checkouts appear beneath it with their branch labels. The root still shows the primary checkout’s branch, upstream, and status details.

A **Checkout** is the terminal workspace that owns tabs and panes. The primary Checkout is the Repository’s root; linked and detached Checkouts are its children. Closing a Checkout only closes Herdr runtime state. It never removes its directory or branch; use the explicit worktree removal action to remove a linked checkout.

The New worktree dialog resolves its displayed Base to an exact commit. Select `[change]` (or press `tab`) to edit the ref. A successfully used Base becomes the Repository preference. When the branch already exists, Git checks out that branch directly, the Base is explicitly marked ignored, and the preference is unchanged.

Existing `workspace.*` automation remains compatible and addresses Checkouts or standalone Spaces. New integrations should prefer `repository.*` and `checkout.*`.

## Tab

A tab is a layout inside a workspace. Use tabs to separate views like `agents`, `logs`, `server`, or `review`.

Tabs are addressable from the CLI and socket API.

## Pane

A pane is a real terminal. Herdr renders the terminal output, sends input back to the process, and preserves the pane across client detach.

Panes can be split right or down. They can be renamed manually, read from the CLI, sent input, and closed.

## Pane collection

A pane collection presents several ordinary panes as a nested, scrollable list in one typed layout leaf. Every member keeps its own pane ID, PTY, process, history, agent state, and API access. Collections support multiple inline previews, collection-local maximize, and active/archive sections.

Archiving is explicit organization: it neither stops the process nor proves success. Input or `working`/`blocked` state restores an archived member. Panes move between tiled placement and collections without restarting. Closing a non-empty collection requires cascade-closing every member PTY or promoting members back to ordinary placement.

## Delegation

Delegation records parentage and purpose independently of placement and agent detection. Stable IDs such as `d1` survive movement and archival; parent provenance remains while descendants exist after a parent pane closes. Collections also work for unrelated shells, tests, and logs without delegation metadata.

## Mouse UI

Herdr is mouse-native. You can click panes, tabs, workspaces, and agents. You can drag split borders, select text, and use right-click menus. Everything below is also reachable by mouse; keyboard bindings are an optional layer.

If you prefer keyboard-only control, or you want Herdr to stop capturing mouse input, disable mouse capture:

```toml
[ui]
mouse_capture = false
```

## Agent

An agent is a process Herdr recognizes inside a pane. Herdr detects agents from foreground processes, screen manifests, and optional integrations.

Agent states are:

| State | Meaning |
| --- | --- |
| `blocked` | The agent needs input, approval, or a decision. |
| `working` | The agent is actively running. |
| `done` | The agent finished and you have not looked at it yet. |
| `idle` | The agent is finished or waiting and has been seen. |
| `unknown` | Herdr cannot confidently classify the state. |

Tiled panes are acknowledged by viewing their active tab. A grouped child is marked seen only when a foreground human enters its terminal; row selection, API focus, reads, and passive observation do not acknowledge it.

## Session

A session is a persistent Herdr server namespace. The default `herdr` command attaches to the default session.

Named sessions are separate runtime namespaces:

```bash
herdr session list
herdr session attach work
herdr session attach side-project
```

Use workspaces first. Use named sessions when you need completely separate panes, sockets, and persisted runtime state.

## Client and server

By default, Herdr runs as a background server plus one or more attached clients.

The server owns panes and process state. The client is the terminal UI attached to that server.

Detach the client with `ctrl+b q`. The server and agents continue running.

If you want to end the session and stop its panes, stop the server:

```bash
herdr server stop
```

## Modes

Herdr has terminal mode, prefix mode, and navigate mode.

Terminal mode sends keys to the focused pane. Prefix mode waits for one Herdr action after the prefix key. Navigate mode is the persistent workspace navigation surface.

Press the prefix key, default `ctrl+b`, then an action key such as `c` for a new tab or `w` for workspace navigation. See [Keyboard](/docs/keyboard/) if the prefix idea is new to you.
