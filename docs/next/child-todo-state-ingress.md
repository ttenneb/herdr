## Frozen minimum verification before implementation

1. **Accepted child socket/API negative and positive test** for TPM/Pi-owner schema review: an accepted *current child* stream with a fresh, acknowledged exact parent route accepts `{protocol:"mailbox.v1",localRoot,localRevision,stateDigest,state:"not_done"|"done"}` only. The server derives complete child/parent delegation, pane, terminal, `herdr:pi` session path, process generations, route revisions and epoch, fsyncs and reads the exact record back before replying `{type:"todo_state",cursor,routeEpoch}`. Retry of the exact frame is idempotent; changed digest/state at the same revision, decreasing revision, changed root, invalid digest/protocol/state, extra route/caller fields, forged binding and a stream accepted before route-ready fail without an ACK. Consumer: TPM for identity/contract and Pi #127 for producer integration.
2. **Staleness/reconnect/replay test** for TPM: reparented/replaced stream cannot use an old edge/epoch; a fresh accepted stream after a new `route_ready` has a distinct epoch and cannot inherit former route's Todo attestation. ## Wire and authority boundary

`todo_state` is a child-stream method, not a generic API or CLI mutation. The only wire selectors are the protocol, one stable local root (1–128 bytes), strictly increasing positive local revision, lowercase hex SHA-256 digest and the two-state enum. All route fields come from `bound_parent_report_current` and `child_report_route_identity`, which recheck verified foreground Pi, both active process generations, full `herdr:pi` sessions, exclusive session writer and acknowledged edge epoch. Same-revision exact duplicate is an idempotent fsynced observation; changed root or revision rollback conflicts. An ACK means only that Herdr durably observed a current child-stream claim. Pi #127 must independently prove it was emitted *after* a fsynced canonical Todo root update, not from model text or idle. `report_coverage` remains observed-only/false, so `done` alone can never qualify missing.
