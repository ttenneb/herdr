## Exact wire and journal scope

Authenticated *child* bootstrap stream method `report_prepared` accepts only protocol `mailbox.v1`, Todo-local root/revision, immutable report ID/report digest, and immutable Submit `stableId/revision/digest/deliveryDigest/messageId` selectors. It accepts no caller, recipient, grant, parent, session, terminal, generation or epoch selector. Server derives those from `bound_parent_report_current` / exact `route_ready`, appends `Prepared` to the existing exclusive fsynced mailbox journal, and returns the durable cursor plus current epoch. Same preparation is idempotent without a second record; a reused report ID, message ID, stable ID or delivery digest with different content/root/route is rejected. A revoked/replaced route cannot prepare or submit.

A future trusted Pi-owner `todo.local_state` producer is still required; no Herdr API trusts Pi idle. Child-stream `report_coverage` accepts only protocol, Todo-local root and revision, derives the exact route, atomically sets `throughCursor` to the locked journal's preceding cursor, fsyncs, and returns `coverageQualified:false`. This **observed-only** barrier is not evidence of Todo completion *or* proof that all delivery paths were closed. It cannot yield `missing_after_done_no_admitted_receipt`. A qualified `all_paths_trusted` barrier exists in the internal projection contract only: there is deliberately no public wire method that can mint it. The missing disposition remains unreachable in production until Pi #127's authenticated durable Todo producer and an independently reviewed all-path closure proof can certify it without relying on a child's unilateral assertion. Even then, the current full-route Todo-done revision, qualified coverage, exact prepared attempts/receipts and mailbox journal must join. Old #121 attempts/coverage have no report-root association and remain legacy uncertain. An admitted report from an older root/revision cannot satisfy a newer root/revision. An unresolved prepared send/attempt remains in-flight/uncertain across restart. Legacy or bypass report delivery is never silently reclassified as an exact prepared route.

The store also refuses a bound-parent `report` head without a prior exact prepared attempt; the connected handler refuses an unprepared send before recording either attempt or head. Same-preparation retries are idempotent, but conflicting IDs/digests are rejected. Typed head+receipt still have an unavoidable crash gap; a prepared attempt without a durable matching admitted receipt remains uncertain. Generic offline and PTY `handoff.send` reports on an identifiable ready route append an fsynced bypass marker before send, and marker failure aborts send. A report on an unverified/not-yet-ready graph, a generic prompt that carries report-like text, or a direct/off-server sender cannot yet be exhaustively identified as a report; this is the **exact coverage blocker**, not permission to infer absence. Existing beta paths remain available and are not silently migrated.

Parent read-only `delegation.child_report_disposition` uses `MailboxStore::existing`, creating neither directory nor lock; absent store returns an empty read projection only after exact parent/route validation. Its cursor remains monotonic across journal replay and cannot submit, claim or complete Todo work.

## Frozen minimum verification plan

1. **Prepared admission/socket tests** for TPM/Pi owner: only current accepted child can prepare; extra route selectors, bad digest, old binding and wrong Pi generation fail. ACK follows durable journal readback. Retry is idempotent; conflicting same selectors fail; prepared token/route cannot cross parent, session, terminal, generation or epoch.
2. **Report race/recovery tests** for TPM release gate: unprepared typed bound send fails without attempt/head/receipt; exact prepared send creates attempt before admission; crash after prepare or after attempt but before receipt is uncertain after fresh store; exact admitted receipt joins only same Todo root/revision/report ID/digest; newer Todo revision does not inherit old admission. Torn/corrupt journal, replaced lock or failed append cannot acknowledge prepare, coverage or send.
3. **Legacy/bypass matrix tests and static review** for TPM: accepted self `report_submit` and generic offline beta grant remain operational but cannot become a prepared bound route; cross-parent legacy report and `handoff.send` produce uncertainty/no false missing; default-off direct transport has no live Herdr binding; if a route cannot be observed/gated, block coverage rather than infer absence.
4. **Read-only test**: exact parent query against an absent store creates no directory and returns unknown, not missing; stale parent rejected; monotonic cursor preserved on restart.

No source edit itself establishes runtime Pi producer compliance. In particular, this checkpoint offers a durable typed send barrier and nonqualifying coverage observation, **not** an authoritative all-paths-qualified missing-after-done result. Pi #127 must prove/exclude unverified legacy and off-server delivery and supply the trusted Todo revision/closure attestation before a later independently reviewed change may mint qualified coverage. Stop/report this impossible-coverage boundary rather than weaken the contract.
